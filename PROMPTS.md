# PROMPTS.md — ключевые промпты проекта

## Этап 1 — Промпт-инжиниринг и ТЗ

**Промпт для составления спецификации:**
> Спроектируй финансовый дашборд-трекер расходов для одного пользователя. Нужна спецификация: целевая аудитория, 3-4 user story, структура данных транзакции (сумма, категория, дата, тип доход/расход, заметка), какие фильтры и графики нужны для анализа трат.

**Результат (ТЗ):**
- **Целевая аудитория:** люди, которые хотят вручную и быстро отслеживать личные расходы/доходы без сложных банковских интеграций
- **User Stories:**
  1. Как пользователь, я хочу добавить транзакцию (сумма, категория, дата, тип), чтобы вести учёт трат
  2. Как пользователь, я хочу фильтровать транзакции по периоду и категории, чтобы анализировать конкретный срез трат
  3. Как пользователь, я хочу видеть графики распределения расходов по категориям и динамику по времени, чтобы понимать паттерны трат
  4. Как пользователь, я хочу получить AI-инсайт по своим тратам простым языком, чтобы не анализировать цифры самому
- **Структура данных:** `{ id, type: 'income'|'expense', amount, category, date, note }`

## Этап 2 — Генерация UI

**Инструмент:** Cursor + Tailwind CSS (ручная сборка компонентов React/TS, без v0.dev/Bolt — для полного контроля над логикой состояния)

**Промпт для главного экрана:**
> Собери layout дашборда: шапка с общей сводкой (баланс/доходы/расходы за период), панель фильтров (диапазон дат, категория, тип), два графика (pie по категориям, line по времени), форма добавления транзакции, список транзакций с возможностью удаления. Тёмная тема, адаптивная сетка.

## Этап 3 — Базовая логика и локальный запуск

**Промпт для стейт-менеджмента:**
> Реализуй хранение транзакций в localStorage через кастомный React-хук useTransactions с методами add/remove и мемоизированной фильтрацией по датам/категории/типу без лишних ре-рендеров.

## День 2, Этап 1 — AI-инсайты

**Промпт для серверлесс-функции:**
> Напиши Vercel serverless function, которая принимает агрегированную сводку трат по категориям (без персональных данных) и возвращает через Groq API 2-3 предложения на русском с наблюдением о паттернах трат и одной рекомендацией. API-ключ только на сервере, не в клиентском коде.

## Ошибки/галлюцинации AI и как исправлены

- Изначально Cursor сгенерировал вызов Groq API прямо из фронтенда с ключом в `.env` через `VITE_` префикс — это раскрывает ключ в бандле клиента (виден в devtools). Исправлено: вызов вынесен в серверлесс-функцию `/api/insights`, ключ хранится только в переменных окружения Vercel на сервере
- AI предложил использовать `Date.now()` как id транзакций без проверки на коллизии при быстром добавлении нескольких записей подряд — заменено на `crypto.randomUUID()`
- AI изначально использовал модель `llama-3.3-70b-versatile` для Groq API — модель оказалась переведена на корпоративный тариф (недоступна по обычному бесплатному ключу), запросы падали с ошибкой 404 `model_not_found`. Исправлено: заменена на актуальную доступную модель `openai/gpt-oss-20b` после проверки списка моделей в документации Groq
